## 3. Об'єктна модель індексу

Для представлення пошукового індексу реалізовано клас `Index`, який наслідує `collections.abc.Mapping`.

Клас підтримує:

- `len(index)` — кількість унікальних термінів;
- `"python" in index` — перевірку наявності терміна;
- `index["python"]` — отримання списку входжень;
- `iter(index)` — ітерацію за термінами;
- `repr(index)` — текстове представлення об'єкта.

Для зберігання статистики використано `cached_property`.

Властивості:

- `num_docs` — кількість документів;
- `avg_doc_length` — середня довжина документа;
- `df(term)` — кількість документів, у яких зустрічається термін.

Моделі `Posting`, `DocMeta` та `SearchResult` реалізовані за допомогою `dataclass`.

## 4. Протоколи та duck typing

Для алгоритмів ранжування визначено протокол `Scorer`.

Протокол описує метод `score(index, doc_id, terms)`, який повинен повертати числову оцінку релевантності документа.

Реалізовано дві взаємозамінні моделі:

1. `TfIdf` — оцінювання на основі частоти терміна та його інформативності.
2. `BM25` — алгоритм ранжування, який додатково враховує довжину документа.

Для BM25 використано параметри:

- `k1 = 1.5`;
- `b = 0.75`.

Завдяки duck typing пошукова функція може працювати з будь-яким об'єктом, що реалізує необхідний метод `score`.

## 5. Парсер мови запитів

Реалізовано парсер методом рекурсивного спуску.

Підтримуються:

- `AND` — логічне перетинання;
- `OR` — логічне об'єднання;
- `NOT` — заперечення;
- круглі дужки;
- фразовий пошук у подвійних лапках;
- неявний `AND` між сусідніми виразами.

Для представлення запитів використовуються вузли:

- `Term`;
- `Phrase`;
- `And`;
- `Or`;
- `Not`.

Вузли підтримують оператори:

- `&` — створення `And`;
- `|` — створення `Or`;
- `~` — створення `Not`.

Кожен вузол має метод `evaluate(index)`, який повертає множину ідентифікаторів документів.

Для фразового пошуку зберігаються позиції термінів у документах.

Приклад запиту:

```text
python AND (async OR await) NOT java "event loop"
```

## 6. Ранжування результатів

Пошукова функція `search` виконує такі операції:

1. Розбирає запит на дерево виразів.
2. Отримує документи, які задовольняють булеві умови.
3. Обчислює оцінку кожного документа.
4. Формує об'єкти `SearchResult`.
5. Вибирає перші k результатів за допомогою `heapq.nlargest`.

Результати містять:

- оцінку релевантності;
- ідентифікатор документа;
- назву файлу;
- текстовий сніпет.

## 7. Перевірки рейтингу

Для оцінювання поведінки ранжування використовуються три sanity-check.

| Перевірка | Очікуваний результат |
|---|---|
| Рідкісний термін проти частого | Документ із рідкісним терміном повинен отримувати вищу оцінку за інших рівних умов |
| Багато повторень одного терміна | Двадцяте повторення повинно давати значно менший додатковий приріст оцінки |
| Короткий і довгий документ | Короткий документ з одним входженням може бути вище за дуже довгий документ з одним входженням |

BM25 враховує насичення частоти терміна та нормалізацію довжини документа.

## 8. Оцінювання Precision@5

Для перевірки якості пошуку використовується метрика Precision@5.

Вона показує частку релевантних документів серед перших п'яти результатів:

\[
P@5 = \frac{\text{кількість релевантних документів у топ-5}}{5}
\]

Для оцінювання передбачено десять власних запитів із ручною розміткою релевантності.

Нижче наведено демонстраційний шаблон таблиці. Значення потрібно замінити результатами фактичного оцінювання корпусу.

| № | Запит | TF-IDF P@5 | BM25 P@5 |
|---:|---|---:|---:|
| 1 | python | 0.60 | 0.80 |
| 2 | java | 0.60 | 0.60 |
| 3 | async await | 0.40 | 0.60 |
| 4 | database | 0.60 | 0.80 |
| 5 | algorithm | 0.40 | 0.60 |
| 6 | event loop | 0.60 | 0.80 |
| 7 | programming language | 0.40 | 0.60 |
| 8 | data structure | 0.60 | 0.60 |
| 9 | search engine | 0.40 | 0.60 |
| 10 | software development | 0.60 | 0.80 |

**Примітка:** наведені значення є демонстраційними, а не результатами фактичного запуску на корпусі.

## 9. Декоратори та кешування

Реалізовано декоратор `@timed`, який вимірює час виконання функції.

Він використовує:

- `perf_counter()` для вимірювання часу;
- `functools.wraps` для збереження метаданих функції.

Декоратор застосовується до:

- `build_index`;
- `save_index`;
- `open_index`;
- `search`.

Для кешування результатів пошуку використовується `@lru_cache(maxsize=256)`.

Кеш зберігає ідентифікатори документів для повторних запитів.

Приклад демонстраційного логу:

```text
build_index: 0.120000 seconds
save_index: 0.002000 seconds
search: 0.001500 seconds
Cache miss: python AND async
search: 0.000200 seconds
Cache hit: python AND async
```

Це приклад формату логу, а не фактичні вимірювання.

## 10. Контекстний менеджер

Для відкриття збереженого індексу реалізовано `open_index(path)`.

Він використовує `contextmanager` і конструкцію `try/finally`.

Це гарантує закриття файлового ресурсу навіть у випадку виникнення винятку.

Приклад:

```python
with open_index("index_lab3.bin") as index:
    results = search(
        index,
        "python AND async",
        scorer=BM25(),
        top_k=5,
    )
```

## 11. Генерація сніпетів

Для кожного результату формується текстовий фрагмент навколо найкращого входження пошукового терміна.

Розмір контексту становить приблизно 80 символів до та після входження.

Знайдені терміни виділяються за допомогою форматування `**термін**`.

Це дозволяє швидше оцінити відповідність документа пошуковому запиту.

## 12. Запуск програми

Побудова індексу:

```bash
uv run python -m findex.run_lab3 --build
```

Пошук із BM25:

```bash
uv run python -m findex.run_lab3 \
  --query 'python AND (async OR await)' \
  --scorer bm25
```

Пошук із TF-IDF:

```bash
uv run python -m findex.run_lab3 \
  --query 'python AND async' \
  --scorer tfidf
```

Зміна кількості результатів:

```bash
uv run python -m findex.run_lab3 \
  --query 'python OR java' \
  --top 10
```
