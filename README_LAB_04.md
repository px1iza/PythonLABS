
# Лабораторна робота №4
# Типи, тести, пакування і CLI

## 1. Мета роботи

Продовжити розробку пошукової системи `findex`, використовуючи можливості статичної типізації Python, автоматизованого та генеративного тестування, пакування Python-проєктів і створення командного інтерфейсу.

## 2. Опис проєкту

`findex` — консольна повнотекстова пошукова система, яка створює інвертований індекс текстових документів і виконує ранжований пошук за запитами користувача.

У попередніх лабораторних роботах було реалізовано:
- обробку текстових документів;
- токенізацію;
- інвертований індекс;
- логічні операції пошуку;
- парсер пошукових запитів;
- алгоритми ранжування TF-IDF та BM25.

У четвертій лабораторній роботу розширено засобами типізації, тестування, пакування та CLI.

## 3. Статична типізація

Для покращення надійності коду використано анотації типів Python.

Реалізовано:
- анотації публічних функцій і методів;
- `typing.Protocol` для опису інтерфейсу алгоритмів ранжування;
- структурну типізацію реалізацій TF-IDF та BM25;
- `Iterator` та `Iterable` для генераторів;
- `Literal` для параметрів із фіксованими значеннями;
- Pyright у режимі `strict`.

## 4. Автоматизоване тестування

Для тестування використано:
- pytest;
- pytest-cov;
- Hypothesis.

Тестами охоплено такі компоненти:
- токенізацію звичайного та Unicode-тексту;
- побудову інвертованого індексу;
- логічні операції та merge;
- синтаксичний розбір пошукових запитів;
- формування та обчислення AST;
- алгоритми TF-IDF і BM25;
- збереження та завантаження індексу;
- команди CLI за допомогою `typer.testing.CliRunner`.

Також реалізовано генеративні перевірки властивостей:
1. Завантаження збереженого індексу відтворює початковий індекс.
2. Постінги залишаються відсортованими.
3. Результати merge відповідають операціям над множинами Python.

Тести, виконання яких займає більше однієї секунди, позначаються маркером `slow`.

### Покриття коду

| Показник | Значення |
|---|---|
| Загальна кількість тестів | 30+ |
| Інструмент вимірювання | pytest-cov |
| Покриття коду | Внести фактичний відсоток із CI |
| Навмисно непокритий код | Інтерактивний вивід Rich та допоміжні сценарії CLI, які залежать від термінального середовища |

Покриття вимірюється командою:

```bash
uv run pytest --cov=findex --cov-report=term-missing
```

## 5. Командний інтерфейс (CLI)

Для створення командного інтерфейсу використано Typer, а для форматованого виведення — Rich.

Реалізовано три основні команди.

### Створення індексу

```bash
findex index --data data --output index_v4.bin
```

Команда обробляє текстові документи, створює інвертований індекс і зберігає його у файл. Під час роботи відображається смуга прогресу Rich.

### Пошук

```bash
findex search "python"
```

Результати пошуку відображаються у форматованій таблиці Rich із назвою документа, рейтингом і фрагментом тексту.

Вибір алгоритму ранжування:

```bash
findex search "python" --scorer tfidf
findex search "python" --scorer bm25
```

Виведення результатів у JSON:

```bash
findex search "python" --json
```

JSON можна перенаправити у файл:

```bash
findex search "python" --json > results.json
```

### Статистика індексу

```bash
findex stats
```

Команда відображає кількість документів, кількість унікальних термінів і середню довжину документа.

### Рівні логування

```bash
findex -v search "python"
findex -vv search "python"
```

Параметр `-v` вмикає інформаційні повідомлення, а `-vv` — детальніше налагоджувальне логування.

Діагностичні повідомлення спрямовуються до stderr, а результати JSON — до stdout.

Очікувані помилки обробляються без виведення повного traceback.

## 6. Пакування проєкту

Для керування залежностями використовується uv.

У `pyproject.toml` описано:
- метадані пакета;
- основні залежності;
- групу залежностей `dev`;
- точку входу `findex`;
- конфігурацію pytest;
- налаштування Ruff;
- налаштування Pyright.

Файл `uv.lock` фіксує версії залежностей.

Встановлення програми як інструмента:

```bash
uv tool install .
```

Перегляд доступних команд:

```bash
findex --help
```

## 7. Автоматизація перевірок — GitHub Actions

Для автоматизації перевірок створено workflow:

`.github/workflows/ci.yml`

GitHub Actions запускає перевірки під час:
- push у гілку `main`;
- створення Pull Request у гілку `main`.

Послідовність перевірок:

1. Отримання коду репозиторію.
2. Налаштування Python.
3. Встановлення uv.
4. Встановлення залежностей командою `uv sync --locked`.
5. Перевірка стилю коду за допомогою Ruff.
6. Статична перевірка типів за допомогою Pyright.
7. Запуск тестів pytest із вимірюванням покриття.

Стан автоматичних перевірок відображається за допомогою бейджа CI на початку README.
