# findex

Навчальний проєкт пошукової системи на Python.

**Лабораторна робота №1: ітератори, генератори та обробка текстового корпусу.**

## Мета роботи

Навчитися працювати з ітераторами та генераторами, поступово обробляти текстові документи, використовувати Unicode-нормалізацію та порівнювати ліниві й жадібні обчислення за часом і використанням пам'яті.

## Реалізовано

- `iter_documents()` — генератор, який читає текстові документи по одному.
- `tokenize()` — генератор токенів із Unicode-нормалізацією.
- `collect_statistics()` — обчислення статистики корпусу за один прохід.
- `collect_statistics_eager()` — жадібна версія для порівняння.
- `measure()` — вимірювання часу та пікового використання пам'яті через `tracemalloc`.
- Автоматичні тести для токенізації та читання документів.

## Правила токенізації

- Використовується Unicode-нормалізація NFKC.
- Усі токени переводяться в нижній регістр через `casefold()`.
- Внутрішні апострофи зберігаються: `don't`, `l’amour`.
- Внутрішні дефіси зберігаються: `well-known`.
- Числа вважаються токенами: `2026`, `python3`.
- Пунктуація та підкреслення розділяють токени.

## Запуск

Встановити залежності:

```bash
uv sync
```

Запустити тести:

```bash
uv run pytest -v
```

Перевірити стиль коду:

```bash
uv run ruff check src tests
```

Запустити аналіз корпусу:

```bash
uv run python -m findex.stats data
```

Текстові документи `.txt` потрібно розмістити в папці `data/`.

## Результати експерименту

Для експерименту використано синтетичний корпус із 53 текстових документів. Він складався з трьох початкових текстів і 50 додаткових файлів, створених на їх основі.

- Кількість документів: 53
- Кількість токенів: 120036
- Розмір словника: 27 унікальних токенів

### Порівняння Lazy та Eager

| Метод | Час виконання | Пікова пам'ять |
|---|---:|---:|
| Lazy | 0.197366 с | 0.1050 MB |
| Eager | 0.143028 с | 7.1924 MB |

У цьому експерименті Lazy використав приблизно у 68,5 раза менше пікової пам'яті, ніж Eager.

Eager виконався швидше, але потребував значно більше пам'яті, оскільки зберігав документи та токени у списках. Lazy обробляв документи й токени поступово, тому не накопичував усі проміжні дані.

Результати отримані на невеликому синтетичному корпусі, тому вони демонструють принцип роботи підходів, а не є універсальним показником продуктивності.
